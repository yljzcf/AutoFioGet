# Frame.io 批注收集（Chrome 插件）

定时抓取 Frame.io 分享链接里甲方留下的批注：批注内容、哪个视频、时间码（含时间段）、作者、回复，发现新批注时弹通知，可导出 CSV，并同步到飞书 / Lark 多维表格（每条批注附上时间点的画面截图）。

- 只需要甲方用的**免登录分享链接**（`https://next.frame.io/share/…` 或 `https://f.io/…`），不需要登录 Frame.io。
- 会遍历分享里的所有文件夹和视频。
- 时间码格式 `时:分:秒:帧`，按每个视频自己的帧率计算，与 Frame.io 播放器显示一致。
- 截图是 Frame.io 从原始视频文件渲染的那一帧（和播放器「下载静帧」一样），宽 720 像素；时间段批注有开始、结束两张。

## 安装

1. 打开 Chrome，地址栏输入 `chrome://extensions`。
2. 打开右上角「开发者模式」。
3. 点「加载已解压的扩展程序」，选择本项目里的 `extension` 文件夹。
4. 装好后会自动打开设置页；建议把插件固定到工具栏（点拼图图标 → 图钉）。

更新代码后，在 `chrome://extensions` 里点插件卡片上的刷新按钮即可，已抓取的数据不会丢。

## 使用

1. **设置页 → 分享链接**：粘贴分享链接，点「添加」。会立刻抓取一次（几十个视频大约 10~20 秒）。
2. **检查频率**：默认每 3 小时一次，可改成 1/2/4/6/12 小时。Chrome 开着才会检查；睡眠或关闭期间错过的，下次打开 Chrome 会补上。
3. **有新批注时**：系统通知 + 工具栏图标上的数字（未读条数）。点图标打开弹窗，「未读批注」按视频分组，默认收起，每组显示视频名和新批注数量；打开弹窗本身不会把它们标为已读。
   - **点视频名**展开：每条显示为「批注人 批注 - 时间码：」，下一行是批注内容，左边是那一帧的截图（回复显示它所回复的批注的画面）；
   - **点某条批注**：打开对应视频，并把这条标为已读；
   - **向右滑动**（鼠标拖动，或触控板两指右滑）：左侧露出「👁 已读」，滑过约三分之一宽度后松手即标为已读，滑得不够会弹回原位。滑**某条批注**只标这一条，滑**视频名**会把这个视频的未读批注全部标为已读；
   - 「全部已读」：一次清空未读列表；
   - 想试用滑动效果：设置页「分享链接」下面的「试用弹窗」→「把最近 10 条批注设为未读」。
4. **导出表格**：弹窗里点
   - 「导出全部 CSV」：当前所有批注；
   - 「导出新增 CSV」：上一次导出之后新出现的批注。

   CSV 是 UTF-8（带 BOM），Excel / Numbers / WPS 直接打开中文不乱码，也可以直接导入飞书多维表格。

### 表格列

| 列 | 说明 |
|---|---|
| 分享名称 / 文件夹 / 视频 | 批注在哪个分享、哪个文件夹、哪个文件 |
| 编号 | Frame.io 里的 `#12`；回复没有编号 |
| 类型 / 回复对象 | `批注` 或 `回复`；回复会写明回复的是哪个编号 |
| 开始时间码 / 结束时间码 | 结束时间码只有「时间段」批注才有；回复显示所属批注的时间码 |
| 开始秒数 | 方便排序筛选 |
| 作者 | 只有名字：匿名访问分享时 Frame.io 不返回邮箱 |
| 内容 | 批注原文，保留换行 |
| 创建时间 / 编辑时间 | 北京时间；没改过的批注「编辑时间」为空 |
| 已完成 | Frame.io 里打勾标记完成的为「是」 |
| 视频链接 | 直接打开该视频的审阅页 |
| 首次抓取时间 | 插件第一次看到这条批注的时间 |
| 批注ID | Frame.io 内部 ID，唯一，可用来去重 |
| 截图 | 只在多维表格里有（CSV 不含图片） |

## 同步到飞书 / Lark 多维表格

两种方式，二选一：

- **应用 API（推荐）**：用你自己的自建应用直接写多维表格。支持**截图**、按「批注ID」去重、批注被修改后同步更新，没有工作流每月次数限制。表格在别的组织时，改用其中的「用户身份」。
- **webhook**：不用建应用，但只能推文字，受工作流每月运行次数和循环条数限制。

### 数据表字段

两种方式都用下面这些字段。应用 API 方式按**字段名**写入，字段名要一致；webhook 方式在工作流里手动对应，字段名可以自己定。

应用 API 方式每次同步前会先读一遍表里的列：表里没有的列直接跳过（弹窗和设置页会列出跳过了哪些），不会让整次同步失败；「作者」列也可以叫「批注者」。文本、数字、单选列按上表写入，「已完成」也可以改成复选框；公式、日期等其他类型的列不写入。只有「类型」「已完成」可以用单选：接口不能给单选列新增选项，「作者 / 批注者」等列设成单选的话，遇到新名字整批都会写入失败，所以插件会跳过这类列并提示改回文本。


| 字段 | 类型 | 对应 webhook 里的键 |
|---|---|---|
| 内容 | 多行文本（设为第一列） | `text` |
| 视频 | 文本 | `video` |
| 开始时间码 | 文本 | `tc_start` |
| 结束时间码 | 文本 | `tc_end` |
| 作者 | 文本 | `author` |
| 编号 | 数字 | `number`（回复为 0） |
| 类型 | 单选或文本 | `kind` |
| 回复对象 | 数字 | `reply_to`（不是回复为 0） |
| 开始秒数 | 数字 | `start_seconds` |
| 文件夹 | 文本 | `folder` |
| 分享名称 | 文本 | `share_name` |
| 创建时间 | 文本 | `created_at` |
| 编辑时间 | 文本 | `edited_at` |
| 已完成 | 单选（是 / 否） | `completed` |
| 视频链接 | 超链接或文本 | `link` |
| 首次抓取时间 | 文本 | `first_seen_at` |
| 批注ID | 文本 | `comment_id` |
| 截图 | 附件 | 只有应用 API 方式会写入 |

### 方式一：应用 API（含截图）

1. **准备应用**：在 Lark / 飞书开发者后台用一个自建应用（lark-cli 创建的那个也可以），记下 App ID 和 App Secret（「凭证与基础信息」页）。
2. **开通权限**：给应用开通 `base:table:read`、`base:record:read`、`base:record:create`、`base:record:update`、`docs:document.media:upload`（设置页填好 App ID 后有直达链接），然后在「版本管理与发布」**创建并发布一个新版本**，权限发布后才生效。
3. **加为协作者**：打开多维表格 → 右上角「…」→「更多」→「添加文档应用」，搜索应用名，给「可编辑」。
4. **填到插件**：设置页「同步到飞书 / Lark 多维表格」里填 App ID、App Secret、多维表格链接（打开那张表后复制地址栏，带 `?table=…`；知识库里的表格，`/wiki/…` 链接也可以），点「测试连接」，能看到记录数就对了。
5. 勾选「每次检查后自动同步」并保存。之后每次检查：新批注**连同截图**一起建记录 → 改过的批注更新内容 / 编辑时间 / 已完成 → 给还没截图的旧记录补截图（每次检查截图最多 100 条，其余下次继续）。

新记录建好时截图已经在里面，所以多维表格里「新增记录时」触发的自动化可以直接在消息里引用「截图」字段。某条截图失败（或超出本次的条数上限）时，记录照常先建好，截图下次检查再补；这种记录触发的消息里不会有截图。

App Secret 只保存在本机 Chrome 的插件存储里。

#### 用户身份：写其他组织分享给你的表格

自建应用只能访问它自己组织里的表格。表格在别的组织时，把设置页的「写入身份」改成**用户身份**：插件以你授权的 Lark 账号写入，只要表格把这个账号加为协作者（可编辑）就能写，截图、去重、更新都和应用身份一样。

1. **开通用户权限**：给应用开通用户身份的 `base:table:read`、`base:record:read`、`base:record:create`、`base:record:update`、`docs:document.media:upload`、`wiki:node:read`、`offline_access`（设置页有直达链接），然后创建并发布新版本。
2. **加重定向 URL**：把设置页显示的 `https://<插件ID>.chromiumapp.org/` 加到开发者后台「安全设置 → 重定向 URL」。这个地址跟着插件 ID 走，插件文件夹换了位置要重新加。
3. **授权**：点「用 Lark 账号授权」，在弹出的窗口里登录。有多个组织时，选**应用所在组织**的账号。
4. **共享表格**：让表格所有者把这个账号加为协作者（可编辑）。表格在别的组织时，那个组织要允许对外分享。
5. 点「测试连接」确认，再勾选「每次检查后自动同步」。

授权的有效期：访问凭证 2 小时，刷新凭证 7 天，插件每次同步都会自动刷新并续期。只要 7 天内至少同步过一次，就不用重新授权。授权真的失效时（比如 7 天没开 Chrome，或在 Lark 里取消了授权），插件会弹一次通知，同步暂停，到设置页重新授权即可。写入的记录会显示为这个账号所写。

### 方式二：webhook（只推文字）

插件只推送**还没推送过**的批注，同一条不会重复推。

#### 建工作流

1. 多维表格左下角「新建 → 工作流 → 从空白开始」。
2. 触发条件选「**接收到 webhook 时**」，复制 webhook 地址，粘贴到插件设置页的「Webhook 地址」，点「保存」。
   - 可选：在「安全设置」里开启「凭证校验」，把 token 填到插件的「Bearer token」。开启后限流从 1 次/秒提高到 5 次/秒。
3. 在触发器的「输出设置」里选「**通过发送请求设置**」→ 回到插件设置页点「**发送测试数据**」→ 3 分钟内回飞书点「**生成**」（工作流还没启用时，插件会提示 webhook 未启用，属正常）。如果抓不到请求，改选「手动设置」，把下面这段粘贴到「示例请求体」。请求体结构是：
   ```json
   {
     "source": "frameio-comments",
     "sent_at": "2026-01-01T02:05:00.000Z",
     "count": 1,
     "items": [
       {
         "share_name": "示例分享",
         "folder": "1st Delivery",
         "video": "EXAMPLE_EP01_v01.mov",
         "number": 1,
         "kind": "批注",
         "reply_to": 0,
         "tc_start": "00:00:12:05",
         "tc_end": "00:00:15:00",
         "start_seconds": 12.2,
         "author": "示例作者",
         "text": "这是一条测试批注，用来让飞书生成请求体结构。",
         "created_at": "2026-01-01 10:00:00",
         "edited_at": "",
         "completed": "否",
         "link": "https://next.frame.io/share/00000000-0000-0000-0000-000000000000/view/00000000-0000-0000-0000-000000000000",
         "first_seen_at": "2026-01-01 10:05:00",
         "comment_id": "sample-0001"
       }
     ]
   }
   ```
4. 添加「**循环**」节点：「需要依次处理的数据」选第 1 步返回值里的 `items`；「最大循环次数」按飞书版本填（见下表）。
5. 在循环里添加「**新增记录**」：数据表选第 1 步建的表，每个字段点 ⊕ 引用「当前循环数据」里对应的键。
6. 右上角「保存并启用」。
7. 回插件设置页勾选「每次检查后自动推送新批注」并保存；也可以点「立即推送未同步」马上推一次。

#### 飞书版本的限制

| 飞书版本 | 工作流每月运行次数 | 单个循环最多 | 插件「每批条数」选 |
|---|---|---|---|
| 免费版 / 商业标准版 | 200 次 | 5 条 | 5 |
| 商业专业版 | 5,000 次 | 100 条 | 100 |
| 旗舰版 / 企业版 | 50 万次 | 1,000 条 | 1000 |

- 每推一批算一次运行。「每次检查最多推送批数」默认 20，超出的留到下一次检查再推，避免一次把额度用完。
- 不知道自己是哪个版本：保持 5 条最稳妥。可以先「立即推送」一批，看表里是不是每次都完整进来 5 条。
- **免费版、存量批注很多时**（例如几百条）：用下面的 `scripts/sync-lark.mjs` 直接写入（或在弹窗里「导出全部 CSV」再在多维表格里导入），然后到插件设置页点「全部标记为已同步」。之后插件只推新增的。

## 命令行工具（可选）

不装插件也能抓一次，需要 Node.js 18+：

```bash
node scripts/probe.mjs "https://next.frame.io/share/…"
```

输出 `out/comments.csv`，并打印文件夹 / 视频 / 批注 / 回复数量和作者统计。加 `--json` 会额外保存原始数据。

**用 lark-cli 同步到多维表格**：和插件的「应用 API」方式是同一套逻辑（建缺少的记录、更新改过的、补截图），只是通过已登录的 [lark-cli](https://github.com/larksuite/cli) 发请求，不需要 App Secret，也不占工作流次数。可以重复运行，用来导入存量或补齐遗漏：

```bash
node scripts/sync-lark.mjs "https://next.frame.io/share/…" --base "https://xxx.larksuite.com/base/…?table=tbl…" --dry-run
```

去掉 `--dry-run` 才会真正写入。`--base` 也可以是知识库里的表格链接（`/wiki/…`）。`--as bot` 改用应用身份；`--max-shots 0` 只同步文字不截图。用户身份需要先 `lark-cli auth login --domain base`（连续 7 天没用 lark-cli 才需要重新授权）。

## 已知限制

- 用的是 Frame.io 网页端自己的内部接口（官方 API 需要账号成员权限，分享链接用不了）。Frame.io 改版可能导致失效，到时需要更新插件。
- 作者邮箱拿不到（匿名访问分享时 Frame.io 不返回）。
- 设了密码或需要邮箱验证的分享链接还没测试过。
- 应用 API 方式会把修改过的批注同步到多维表格；webhook 方式不会。两种方式都不会删除多维表格里的记录：在 Frame.io 里删掉的批注，只是不再出现在插件的 CSV 导出里。
- 截图不含甲方在画面上画的标注（目前的批注都没有画标注）。
- 每张截图要 Frame.io 渲染 2~4 秒，所以每次检查最多补 100 条，存量多时会分几次补完。
- 只在 Chrome 开着时定时检查。

## 开发

```
extension/            插件本体（MV3，无需构建）
  background.js       定时检查、通知、角标、飞书同步 / 推送、消息处理
  popup.* options.*   弹窗和设置页
  lib/frameio.js      Frame.io 分享接口（GraphQL）
  lib/rows.js         批注 → 表格行；时间码见 lib/timecode.js
  lib/csv.js          CSV 导出
  lib/lark.js         飞书 / Lark Base v3 API：建记录、更新、上传截图（插件和 sync-lark.mjs 共用）
  lib/oauth.js        用户身份：Lark 账号授权（OAuth）、自动刷新凭证
  lib/feishu.js       webhook 推送（分批、限速、幂等 Client-Token）
  lib/store.js        chrome.storage 读写和新旧批注合并
scripts/
  probe.mjs           命令行抓取
  test-extension.mjs  在 Node 里模拟 chrome API + 本地假 webhook / 假 Lark API，端到端测试 background.js
  preview-server.mjs  在普通浏览器里预览弹窗和设置页（注入假 chrome API）
  sync-lark.mjs       用 lark-cli 同步到多维表格（含截图，按批注ID去重）
  make-icons.mjs      生成图标
```

```bash
node scripts/test-extension.mjs "https://next.frame.io/share/…"
```
